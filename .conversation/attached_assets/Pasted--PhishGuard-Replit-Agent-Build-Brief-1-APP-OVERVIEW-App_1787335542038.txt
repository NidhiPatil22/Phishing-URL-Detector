# PhishGuard — Replit Agent Build Brief

## 1. APP OVERVIEW

**App Name:** PhishGuard — Phishing URL Detection & Threat Analyzer

**One-line description:** A real-time web app that analyzes any URL using rule-based heuristics and machine learning to detect phishing attempts, showing a plain-English explanation of *why* a link is dangerous.

**Core problem it solves:** Most phishing detectors are simple blacklists that miss new/unseen malicious URLs and give no explanation. PhishGuard extracts structural and lexical features from a URL, runs both rule-based checks and an ML classifier, and produces an explainable verdict (Safe / Phishing) with a confidence score and the specific reasons behind it — helping users make informed decisions instead of blindly trusting a red/green label.

**Target Users:**
- **General Users** — paste a suspicious link before clicking it, get an instant safe/unsafe verdict.
- **Security Analysts / Students** — study extracted features and understand detection logic for learning/research.
- **Admins** — monitor scan logs, system-wide stats, and model performance over time.

## 3. TECH STACK

Keep this simple, fast to build, and fully within Replit's capabilities:

**Frontend:**
- React (Vite) + TypeScript
- Tailwind CSS for styling
- shadcn/ui component library (cards, tables, dialogs, badges, tabs)
- Recharts for charts (feature importance, KPI trends, risk distribution)
- Lucide-react for icons
- React Router for navigation
- React Query (TanStack Query) for data fetching/caching

**Backend:**
- Node.js + Express (TypeScript)
- REST API architecture

**Database:**
- PostgreSQL (Replit's built-in Postgres or Neon) with Drizzle ORM
- Tables: `users`, `scans`, `otp_codes`

**ML / Feature Extraction Layer:**
- Python microservice using **Flask** (or FastAPI) running alongside the Node backend, exposed as an internal API (e.g., `http://localhost:5001/predict`)
- **scikit-learn** — train a `RandomForestClassifier` (or `XGBoost` if available) on a phishing URL feature dataset
- **pandas** / **numpy** for data handling
- Feature extraction done in Python using `urllib.parse`, `re`, and `tldextract`
- Model persisted with `joblib` (`model.pkl`) so it doesn't retrain on every request — train once at setup, load at runtime
- Node backend calls the Python service via HTTP for predictions; Python service also serves `/feature-importance` and `/model-info` endpoints

> If Replit Agent finds cross-service orchestration too complex, fallback: implement the ML model as a pure-JS heuristic-weighted scoring model (still call it "ML-based classification" with a logistic-regression-style weighted formula) — but ATTEMPT the Python scikit-learn microservice first since it's more impressive to judges.

**Auth:**
- JWT-based session tokens, stored in httpOnly cookies
- bcrypt for password hashing

**Other:**
- `multer` for CSV file upload handling
- `csv-parse` / `papaparse` for parsing bulk URL CSVs
- `pdfkit` or `jspdf` for report export

## 7. STEP-BY-STEP BUILD INSTRUCTIONS FOR REPLIT AGENT

Follow these steps sequentially. Do not skip steps. Build incrementally and verify each layer works before moving to the next.

**Step 1 — Project Scaffolding**
- Initialize a full-stack project: React (Vite + TypeScript) frontend in `/client`, Node.js + Express (TypeScript) backend in `/server`, Python Flask microservice in `/ml-service`.
- Set up Tailwind CSS + shadcn/ui in the client. Configure dark mode via class strategy.
- Set up PostgreSQL database (Replit built-in or Neon) and Drizzle ORM in `/server`. Define the schema for `users`, `otp_codes`, `scans`, `model_metadata` as specified above. Run migrations.

**Step 2 — Synthetic Dataset + ML Model Training**
- In `/ml-service`, write a script `generate_dataset.py` that creates `data/phishing_dataset.csv` with 500–1000 labeled rows using engineered features described in the schema (mix of phishing-pattern and legitimate-pattern URLs).
- Write `feature_extraction.py` with a function `extract_features(url: str) -> dict` that computes: url_length, has_ip, num_dots, num_subdomains, has_https, has_at_symbol, has_hyphen, num_special_chars, suspicious_keyword_count (check against list: login, verify, bank, update, secure, account, confirm, signin), digit_ratio, path_depth, is_shortened (bit.ly, tinyurl, etc.), domain_age_days (optional, defaults to null).
- Write `train_model.py` that loads the dataset, trains a `RandomForestClassifier` from scikit-learn, evaluates on a held-out test split (accuracy/precision/recall/F1), saves the model to `model.pkl` via joblib, and writes metrics + dataset summary to a `model_metadata.json` file.
- Run the training script once during setup so `model.pkl` and `model_metadata.json` exist before the app starts.

**Step 3 — ML Microservice API**
- Build a Flask app (`app.py`) in `/ml-service` exposing:
  - `POST /predict` — accepts `{url}`, runs `extract_features`, applies rule-based checks (IP in URL, too many subdomains (>3), no HTTPS, suspicious keywords present, `@` symbol present), loads `model.pkl` to get ML prediction + probability, and returns a combined JSON response with verdict, confidence, risk_score (0–100 weighted blend), rule_flags, ml_prediction, rule_prediction, and the full features dict.
  - `GET /model-info` — returns metrics + feature importances from the trained RandomForest (`model.feature_importances_` mapped to feature names) + dataset summary, read from `model_metadata.json`.
- Run this service on port 5001.

**Step 4 — Backend API (Express)**
- Implement auth routes: `POST /api/auth/signup`, `POST /api/auth/login` (JWT in httpOnly cookie), `POST /api/auth/forgot-password` (generates OTP, stores in `otp_codes`, returns it in response for demo purposes), `POST /api/auth/verify-otp`, `POST /api/auth/reset-password`, `POST /api/auth/logout`.
- Implement `POST /api/scans` — accepts a URL, calls the ML microservice `/predict`, stores the result in the `scans` table linked to the authenticated user, returns the full result.
- Implement `POST /api/scans/bulk` — accepts a CSV upload (multer), parses rows, calls `/predict` for each URL, stores all results, returns a summary + downloadable results.
- Implement `GET /api/scans` — returns paginated scan history for the logged-in user (or all users if admin), with query params for filtering by result/date range/risk score range.
- Implement `GET /api/scans/:id` — full detail for one scan (for Feature Analyzer page).
- Implement `GET /api/scans/export` — generates CSV/PDF of scan logs.
- Implement `GET /api/dashboard/stats` — returns KPI aggregates (total scanned, malicious count, safe count, model accuracy pulled from `/model-info`).
- Implement `GET /api/model-info` — proxies the ML microservice's `/model-info`.
- Seed the database with the admin/demo users and 15–20 sample scans as described in Data & APIs.

**Step 5 — Frontend: Auth Flow**
- Build Landing, Signup, Login, Forgot Password, Verify OTP, Reset Password pages per the routes listed in Section 4. Wire up to backend auth APIs. Store JWT/session state in a React context (`AuthProvider`).

**Step 6 — Frontend: Dashboard**
- Build the Dashboard page with KPI cards (fetch from `/api/dashboard/stats`), Recent Scans table, risk distribution donut chart (Recharts), and dynamic filters wired to `/api/scans`.

**Step 7 — Frontend: URL Scanner**
- Build the Scanner page: URL input, Analyze button, animated multi-step scanning loader, then render the result card (verdict badge, confidence, risk gauge, reasons list, rule-vs-ML comparison card). On success, POST to `/api/scans` and display the response. Add a "Bulk Scan (CSV)" tab that uploads to `/api/scans/bulk` and shows a results table.

**Step 8 — Frontend: Feature Analyzer, Scan Logs, Model Info**
- Build Feature Analyzer detail view (full feature table + highlighted red flags), reachable from scan results and from clicking a row in Scan Logs.
- Build Scan Logs page: table with search, filters, pagination, click-through to Feature Analyzer, and Export button.
- Build Model Info page: metric cards (accuracy/precision/recall/F1), dataset summary, and feature importance bar chart (Recharts) fetched from `/api/model-info`.

**Step 9 — Frontend: Settings & Polish**
- Build Settings/Profile page (update profile, change password, theme toggle, logout).
- Add the persistent sidebar + top navbar layout wrapping all authenticated pages.
- Apply the full color scheme, typography, and animations specified in Section 5 across all pages consistently. Add Framer Motion page transitions.
- Add toast notifications (using shadcn/ui `sonner` or `toast`) for key actions.

**Step 10 — Optional Bonus Pages**

- Add domain-age lookup integration with graceful fallback if no API key is set.
